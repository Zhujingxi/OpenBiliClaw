# Target Frontend Workspace

`frontend/` is the Presentation Contract npm workspace. The shared contracts, responsive Vue web shell, and slim extension shell are implemented.

## Implemented

- The root workspace declares `packages/api-client`, `packages/presentation`, `apps/web`, and `apps/extension`; dependencies for all four packages are recorded once in the lockfile.
- TypeScript enables `strict`, `allowJs=false`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `noImplicitOverride`, and `useUnknownInCatchVariables`.
- `api-client/generated/schema.ts` is generated from deterministic FastAPI OpenAPI with workspace-pinned `openapi-typescript@7.10.1`; `scripts/generate_api_client.py` downloads no temporary tools.
- `ApiClient` validates unknown JSON through caller-supplied type guards. HTTP, network, and invalid responses become safe typed failures; safe messages from typed API error envelopes reach the UI. SSE event envelopes are runtime-validated at the boundary, preserving the server `retry:` hint for the reconnect owner. Browser mutations include the generated `/v1/feedback` operation and consistently attach device/CSRF headers.
- The Presentation package reuses generated API projection types and defines provider views, card descriptors/actions, pagination, and availability UI contracts.
- Video/image/article/discussion/fallback Vue cards share one responsive `CardShell`. Desktop grid rows are equal height; 16:9 media or provider placeholders, two-line titles, three-line summary slots, metadata, and feedback actions use fixed hierarchical alignment. Mobile single-column cards remove text minimum heights to avoid empty space. Every content provider and card kind reuses this shell; provider-specific card geometry is prohibited. Card controls share an accessible outer frame, feedback controls emitting `like`/`dismiss`, and provider/status presentation. The web recommendation store retains feed `shown_id` in the card view model, records viewport exposure with native `IntersectionObserver`, and includes `exposed` in dismiss feedback. It displays results only after `/v1/feedback` succeeds, and presents 404/409 delivery expiry as a visible error. Card titles navigate to an internal detail route carrying an encoded `ContentRef`; details retain HTTP(S) provider canonical links. A 1970 epoch sentinel is not shown as source time, and blank or dash-only placeholder summaries are not rendered. HTTPS image URLs in cards and content details are always rewritten to same-origin `/v1/media?url=…`; browsers never request provider CDNs directly, preventing Referer/access-IP leakage while provider hotlink headers come from the backend manifest. Vue escapes text. The renderer accepts only the build-time `generic` marker, never backend HTML/CSS/component names/code.
- A Python CI test scans the workspace and rejects checked-in `.js`/`.mjs`/`.cjs`; every `dist/` is in `.gitignore`.

## Development commands

```bash
npm --prefix frontend install
PYTHONPATH=src:. .venv/bin/python scripts/generate_api_client.py
npm --prefix frontend run format:check
npm --prefix frontend run lint
npm --prefix frontend run typecheck
npm --prefix frontend run test
npm --prefix frontend run build
```

Generated `schema.ts` may be committed and must be reproducible. Vite `dist/` is ignored build output and must not be committed.

## Web shell (Phase 14b)

`apps/web/` is one responsive Vue app, not separate desktop/mobile apps. A shared neutral semantic-token layer fixes card, field, badge, focus, spacing, and responsive behavior. Brand and interaction accents are blue; status colors are limited to green (healthy), yellow (warning), and red (error). Desktop uses a grouped sidebar plus sticky workspace bar; mobile uses five-item bottom navigation. Both share recommendations, content-source cards, search/content detail, profile, Assistant, layered source setup, settings, and runtime-health views.

The web shell supports `en`, `zh-CN`, and `zh-TW` through one typed `vue-i18n` bootstrap and complete static catalogs. On first use it matches the browser language (English fallback), persists the selected tag locally, switches without reload, and synchronizes `<html lang>` and route titles. Settings → Appearance exposes the language selector; Assistant turns pass the selected supported tag verbatim and do not add streaming behavior.

Pinia stores are split by durable concern: session, sources, recommendations, content, profile, Assistant, runtime/jobs, model catalog/configuration, auth, and host-local preferences. Every server store explicitly exposes idle/loading/success/empty/error and cancels stale requests with `AbortController`. The auth store owns the runtime-health startup probe, avoiding duplicate reads on recommendation cold load: 200 without a token means no password is enabled; 401 routes to `#/login`; other failures fail closed to login. It also owns token persistence in localStorage and the authenticatedFetch wrapper, which injects `Authorization: Bearer` per request. Only a 401 from a request that actually carried a stored token clears the token and routes to login; product-level 401 without a token remains for the calling view to display. The wrapper binds the globalThis receiver to avoid Chrome detached-fetch "Illegal invocation". Login is unguarded; other hash routes redirect to `#/login` when authentication is required. Content search/detail has independent phase/error/request ownership to prevent cross-view leakage; the detail hash carries JSON `ContentRef` and refetches when its parameter changes on the same route. Runtime store is the sole event-stream owner, preferring server `retry:` hints and otherwise using bounded 100ms→500ms→1s→2s reconnect backoff while retaining at most 50 event envelopes. Mutations such as profile edits do not optimistically update without rollback; server responses remain authoritative.

The Settings Model zone searches/browses providers and models from `/v1/models/catalog`. Providers appear as expandable native `details` rows and sit beside model configuration on desktop, with the current provider pinned first. Explicit provider/model fields show catalog protocol/environment metadata and support endpoint overrides and write-only password keys. Model provider/name, model and embedding credential presence, embedding provider/name/endpoint, `reloaded`, and `restart_required` from `/v1/models/current` appear in a separate Active runtime card; save messages follow server status. The advanced custom-provider form requires protocol, endpoint, and full capabilities, matching the backend escape hatch. Appearance is a separate zone. Loading, empty, error, saving, and save-failure states are accessible. The current host contract persists only one active chat model; the UI does not invent a multi-key profile registry.

Accessibility includes a skip link that does not obscure the brand, localized desktop/mobile navigation and ARIA labels, clear `aria-current` treatment, a localized document title per route, unknown-route fallback notice, form labels and nearby guidance for ambiguous values, loading/error live announcements, route-heading focus, Alt+Left navigation, visible focus/invalid field treatment, a high-contrast palette, and system/user reduced-motion policy. Endpoint guidance explicitly requires API base URLs without `/v1` and provides a loopback-safe example; secret inputs are write-only UI fields with local-vault/browser-local handling explained without redisplaying saved values. At 390px, mobile navigation remains five core destinations; form controls and card grids shrink within the viewport. The Recommendations secondary refresh action calls supervised `/v1/recommendations/refresh` before reading the authoritative feed. Empty feed/provider/search/profile/content-detail states explain why and offer Connect/Search CTAs. Content Sources is an operational dashboard: overview shows connected/available sources, active candidate pool, selected-or-shown feed queue, and video queue; content-kind distribution, queue provider distribution, and terminal archive explanation come from typed `/v1/sources` inventory. Provider cards also show account, connection method, verification, capabilities, and per-provider pool/queue. Connect separates provider, access method, and credential into three clear levels and shows all states in an accessible live status list before and after connection. Assistant is a full-height chat window: complete server/local turn history uses role bubbles; empty conversations offer prompt suggestions; pending responses show typing feedback; turn failures appear inline; missing capabilities link to Settings; and the composer stays at the bottom with Enter / Shift+Enter behavior. Server-hydrated structured output and live output use the same safe plain-text projection and never display persisted raw JSON or opaque recommendation IDs. Runtime shows a health badge, check time, supervised jobs, expandable recent events, and manual refresh. Store/component/view tests cover these states and navigation/keyboard paths.

## Extension shell and packaging

`apps/extension` connects to the loopback backend and persists only its URL and the opaque token generated by `openbiliclaw ext-token`. The popup uses no provider-specific background/content script. It enumerates providers from `/v1/sources`, requests a declarative recipe for each (skipping 404), dynamically requests HTTPS optional host permission from the recipe, reads only declared cookie/local-storage/session-storage keys through generic `chrome.cookies` or tab-scoped `chrome.scripting`, then submits the material with bearer + device/CSRF headers. The popup uses its own maintainable `vue-i18n` seam for `en`, `zh-CN`, and `zh-TW`, with the same detection, fallback, persistence, and live-switch behavior as the web shell. Its visible language selector, localized state/ARIA text, explicit base-URL guidance (no `/v1`), and write-only token input are packaged with standard manifest `_locales`; the release tool copies those declarative catalogs unchanged. The manifest requests only generic `cookies`/`scripting`/`tabs`/`storage` primitives and `https://*/*` optional host permission; it contains no provider ID, cookie name, refresh schedule, in-page fetch/signing, or behavior collection. The Python release tool writes all generated output to ignored `artifacts/extension/`. The production host serves the web Vite artifact as an SPA; installer and Docker pipelines build it first. SPA `index.html`/route fallbacks use `Cache-Control: no-cache`, while fingerprinted Vite `/assets/*` artifacts use one-year immutable caching so old HTML does not continue referencing stale bundles after rebuilds.
