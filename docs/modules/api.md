# API Host

The current FastAPI host is `openbiliclaw.hosts.api`. It exposes strict `/v1` transport schemas over the same Application workflows used by composition.

## Routes

- `POST /v1/auth/login` verifies the configured PBKDF2 password and returns a one-time session bearer token; it is bearer-exempt but retains origin, CSRF, body, timeout, and rate-limit controls
- `GET /v1/media?url=<HTTPS URL>` proxies only `image/*` responses from provider-declared CDN hosts, forwarding that provider's declarative static image headers. It rejects IP/userinfo/port/host tricks, non-images, responses over 10 MiB, redirects/failures, and slow upstreams. It is bearer-exempt because the objects are public and the allowlist prevents open-proxy use; normal origin, timeout, and rate limits remain. No video/audio or server-side media cache is provided
- `/v1/sources` returns connection/capability rows plus recommendation inventory: active candidate-pool count, selected-or-shown feed-queue count, terminal archive count, and active pool/queue breakdowns by provider and content kind. Source form/connect/disconnect share the same route group; connect accepts the provider form's secret `submission` mapping unchanged, supports credential-free `builtin.anonymous` connections such as YouTube, returns typed 404 for an unknown provider, and returns typed validation errors for unsupported method/scope combinations instead of a generic 500. `GET /v1/sources/{provider}/access-recipe` returns provider-declared browser artifact data (typed 404 when absent), while `POST /v1/sources/{provider}/access-material` accepts the exact declared artifacts and converges on the same form/verifier/vault path. Both plugin endpoints require static or minted bearer auth; the POST also requires matching device/CSRF headers
- `/v1/recommendations` delivers selected items, marks them shown, and returns a stable `shown_id`; supervised refresh remains a separate bounded mutation. Delivered cards preserve validated provider thumbnail URLs for the allowlisted media proxy, while provider-unknown publication timestamps serialize as `null`, never the Unix epoch sentinel
- `/v1/feedback` accepts `idempotency_key`, delivered `shown_id`, matching `content_ref`, and a feedback kind (`liked`/`dismissed` for the Web controls); it transitions the recommendation to interacted and atomically records its learning observation. Unknown shown IDs return the typed `not_found` envelope
- `/v1/observations` accepts explicit typed observation batches
- `/v1/profiles/{profile_id}` and profile edit
- `/v1/content/search`, `GET /v1/content/detail?reference=<JSON ContentRef>`, and propose/confirm/reject actions. `POST /v1/content/actions/reject` scopes by user, durably cancels pending or expired proposals, and conflicts after approval. Detail references use a query parameter because canonical URLs cannot safely occupy one path segment; malformed JSON/identity returns typed 422 and well-formed unknown content returns typed 404
- `/v1/assistant/turns`, scoped conversation reads. Turn context requires the requested locale and recommendation tools expose human-readable titles/canonical links without model-visible delivery IDs
- `/v1/runtime/health`
- `/v1/models/catalog` projects models.dev provider/model metadata for configuration UI
- `/v1/models/current` reads model and embedding settings with credential-presence booleans; `PUT` validates and persists the chat model while accepting API keys write-only into the vault. A process started without a writable `--config PATH` returns a typed 422 explaining that settings cannot be saved
- `GET /v1/events/stream` replays SSE from `after`, stays open, polls the bounded event source for new envelopes, emits keep-alives, advertises the configured `retry:` interval, and stops on client disconnect; `WS /v1/events/ws` performs the same origin/bearer checks, replays the bounded current batch from `after`, then closes
- `/v1/openapi.json`

Model updates return `reloaded=false` and `restart_required=true`: the production process does not yet host its API through `ApplicationReference`, so it cannot safely swap its own graph in place. The narrow writer atomically replaces only `[model]`, `[model.options]`, and `[model.capabilities]`; comments inside those owned tables are not preserved, while all other sections and comments remain byte-for-byte unchanged. Empty/omitted API key input keeps the existing vault reference. API responses expose only `secret_configured`, never references or secret material.

Mutations require matching `X-Device-ID` and `X-CSRF-Token`. Loopback binding may intentionally run without authentication; setting `host.password_hash` enables password login and bearer enforcement. Non-loopback binding requires either password login or a static bearer resolved from the credential vault through `host.bearer_secret_ref`. Static, session, and extension tokens protect user-data HTTP and WebSocket routes; minted raw tokens are shown once and only SHA-256 hashes are stored. Login has an additional per-process failure bound. The host enforces body, timeout, rate, origin, bearer, and websocket subscriber bounds and returns typed JSON error envelopes rather than HTML. The public Vue SPA shell must load to present login, and public allowlisted media is also bearer-exempt; neither exemption exposes user data. SPA HTML fallback responses use `Cache-Control: no-cache`; fingerprinted `/assets/*` files use `public, max-age=31536000, immutable`.
