# Recommendation Pipeline

`openbiliclaw.recommendation` contains the deterministic discovery-to-history pipeline. Candidate state is explicit (`discovered → normalized → prefiltered → evaluated → admitted → selected → shown → interacted/expired`, with terminal rejection) and every transition is checked in Python and enforced by a SQLite transition trigger. Rejections and admissions have dedicated immutable audit tables; selection persists evaluated → admitted → selected atomically. Delivering the Application feed atomically records a deterministic `shown_id` and moves selected → shown; accepted feedback validates that shown record and matching content before moving shown → interacted.

Discovery plans bounded provider-neutral queries from the canonical `default` profile's `DiscoveryProfile`, falls back to deterministic defaults when `recommendation.query` is unavailable, and calls typed provider search capabilities directly. Content-dimension preferences feed discovery interests until the stable-interest analyzer is routed. Discovered previews retain their plan topic as candidate provenance. Hard prefilters apply profile avoidances before the one-shot `recommendation.evaluate` contract; selection applies hard negative topics, then uses named model/freshness/novelty contributions plus provider (2), creator (1), and topic (2) diversity quotas. An optional tuple of exploration attributions reserves matching eligible candidates before normal ranked fill; those slots are hard when matching supply exists and soft-degrade rather than blocking the feed when it does not. The same seed, candidates, evaluations, and constraints reproduce the slate.

The production baseline evaluator is deliberately deterministic and not personalized: accessible candidates receive the same model contribution, then freshness and novelty determine rank. Profile influence currently shapes acquisition query/topic and hard exclusions, not model scoring. Optional `recommendation.expression` stores copy provenance separately and falls back to safe deterministic text.

`RecommendationService.feed()` is model-free and joins selected candidates with their immutable expression reason. It orders the newest run by stored rank and returns score contributions for explainability. Refill processes only newly inserted deterministic candidate IDs; rediscovery of an all-known batch is a successful observable no-op rather than a state retransition. Public refresh bounds discovery with `maximum_items`; scheduled replenishment uses the configured pool target. Discovery, evaluation, expiry and replenishment are Core `JobSpec`s with explicit timeout, resource and non-overlap policies, and host job health comes from `RuntimeSupervisor`.

Semantic acquisition now supplements text-query discovery. Every bounded candidate title/summary/topic fragment is best-effort indexed before inventory admission; the `adjacent` arm performs cosine recall against durable weak/emerging claim vectors and excludes candidates above the established-interest match threshold. Matching candidates retain the allocator's adjacent hypothesis attribution through selection and feedback. Missing configuration, stale-model rows, and provider failures yield empty semantic supply without blocking the normal search/feed path. Recall is pure Python over the bounded local index; no provider payload body, LLM rerank, ANN dependency, or cross-user retrieval is present.

Production composition registers discovery, evaluation, expiry, and replenishment jobs. Feedback enters the Observation workflow; deleted legacy discovery/recommendation engines and producers have no compatibility path. Offline domain evaluation scenarios remain deferred.

## Exploration and anti-cocoon (decided direction)

Exploration/recommendation policy is a **pluggable strategy module**: the pipeline defines the strategy interface (evidence/profile/candidates in, slate guidance out) and strategies can be swapped. The agentic strategy below is the first implementation; seed tactics (weak-signal, dormant-interest, adjacent, bridge, source-novel) ship with it, but arms are not a closed enum.

Landed: `HypothesisRegistry` validates and appends open-arm hypotheses to `PolicyJournal`, lists only unexpired and un-killed hypotheses, records attempt/success/failure/kill events, and exposes raw `(attempts, successes, failures)` counts for later statistical allocation. Falsification remains pre-registered human/agent-readable text: the brief agent evaluates it and records a kill event rather than deterministic code parsing a criterion DSL. Seed arm discovery and registry consumers land with the later brief/evidence/allocation items.

Landed reward contract: `RewardKind` fixes the multi-objective vocabulary before learning starts. Like/save are explicit satisfaction (weight `1.0`) and resolve the supplying exploration hypothesis as success; dislike/dismiss are explicit correction (weight `-1.0`) and resolve only that supplying hypothesis as failure; open is weak meaningful consumption (weight `0.25`) and records exposure without resolving the Beta posterior. Production composition supplies one standing `exploit` hypothesis for unattributed open/like/save, so its funnel and positive posterior learn without treating corrections as profile or exploit decay. `RewardLedger` requires the matching durable shown record, appends attempt before resolution, and is called only after a newly inserted feedback record. Landed evidence discipline copies the candidate's server-resolved exploration arm/hypothesis into every feedback observation; an exploration dismissal records failure only when the client reports viewport exposure (an unexposed dismissal retains the attempt only). Exploration like/save also creates a confidence-0.2 Understanding proposal which remains pending behind the canonical confidence/corroboration gate. Voluntary-return and repetition-fatigue remain vocabulary-only derived outcomes until longitudinal evidence exists.

Landed adjacent supply: `RecommendationProfile` v2 carries opaque embedding claim views; confidence-`0.7` active stable/content claims define established interests, while emerging/lower-confidence claims provide adjacent seeds. Versioned recall defaults require cosine `>=0.70` to a weak claim and `<0.85` to every top claim. Replenishment maintains the adjacent hypothesis, indexes current candidate metadata, recalls from the configured model's durable vectors, and attributes only qualifying candidates; an empty arm soft-degrades through the existing constrained selection path. These are deterministic recall boundaries, while Thompson outcomes continue to learn the arm's magnitude.

Landed statistical allocator and slate wiring: `ThompsonAllocator` is a pure stdlib strategy seam over registry count tuples. A caller-owned `random.Random` makes every Beta draw replayable, and `AllocationDecision.samples` records each hypothesis/strategy draw with its effective alpha/beta. `enjoy`/`accomplish` admit exploit only; `deepen`/`explore` sample active exploration hypotheses only; `uncertain` lets them compete with a first-class exploit posterior. An absent exploit history and every new family start at uniform Beta(1,1), so multiple active exploration hypotheses create elevated cold-start exploration without a fixed percentage. Evidence-less hypotheses borrow resolved outcomes from their strategy family; hypotheses with resolutions use their own evidence. Replenishment now maintains standing `source-novel`, `weak-signal`, and `exploit` hypotheses, samples with the selection seed, records the decision and posterior draws in the policy journal, and passes a winning exploration constraint to selection. The hardcoded uncertain intent remains the live allocator input until RecommendationBrief shadow evidence justifies switching; dormant-interest remains deferred until ledger SQL exists.

Landed RecommendationBrief shadow mode: `recommendation.brief` emits a strict typed proposal containing ephemeral intent, evidence-ID-only hypotheses and kill conditions, channel/keyword retrieval plans, shortlist inspection rubric, qualitative familiar/novel slate relationships, ask/recommend/abstain action, stop condition, and expiry. `BriefCompiler` deterministically rejects undeclared channels, personalized exploration supply, inspection over budget, invalid expiry ordering, and inconsistent questions; percentage allocation is unrepresentable in slate guidance. Each configured-model replenishment invokes `BriefService` before allocation and appends the proposal, acceptance diagnostics, complete channel/budget/privacy compiler inputs, context hash, model route, and agent schema/prompt/context versions to the append-only journal. Model/compiler/journal failure is contained and the existing seeded allocator still executes with `intent="uncertain"`; brief retrieval, inspection, questions, and intent do not execute until a later live-switch decision after shadow evidence.

### Agentic strategy: maximal semantic agency, bounded operational delegation, deterministic execution sovereignty

- **RecommendationBrief**: on material context change the agent autonomously compiles a typed brief — intent (`enjoy | accomplish | deepen | explore | uncertain`, ephemeral and scope/expiry-bound; inferred or asked, never a personality label), evidence-cited hypotheses with pre-registered kill conditions, retrieval/keyword plans (keyword inspiration folds in here; no separate subsystem), inspection targets with a per-context quality rubric, slate guidance as familiar/novel relationships (not percentages), ask/abstain/recommend, stop condition, expiry. A deterministic compiler validates it against capabilities/budget/privacy and logs a replayable trace (context hash, model/prompt/schema versions, brief, compiled result). Intent conditions exploration allocation: `enjoy`/`accomplish` episodes exploit; `deepen`/`explore` episodes use hypothesis channels; `uncertain` asks or defaults to the learned allocation.
- **Reversible internal policy auto-applies** (expiry + audit + rollback); durable user claims still use proposal/corroboration; external mutations, secrets, spend and privacy expansion stay gated. The agent may semantically order a validated shortlist but cannot resurrect excluded candidates, bypass dedup, or exceed budget.
- **Statistics own magnitudes**: Thompson posteriors over hypotheses (strategy-family prior → hypothesis posterior when data exists), decayed rates, constrained-MMR slate construction generalized from the existing provider/creator/topic quotas. Exploration allocation scales down automatically with revealed preference (unviewed or dismissed exploration decays posteriors); only an explicit `exploration.disabled=true` user statement can zero exploration; otherwise the optionality invariant keeps learned exploration reachable. Validity bounds (`quota >= 1` etc.) are type constraints, not policy.
- **Evidence discipline (landed)**: feedback observations retain server-resolved exploration arm/hypothesis identity; dismissals resolve failure only after viewport exposure; like/save-on-explore enters Understanding as a pending low-confidence (`0.2`) proposal through `ProposalPolicy`; a dismiss decays that hypothesis's allocation, never a global ban. `exploration.disabled=true` is an explicit profile override exposed by API/CLI and is the only zeroing input; removing it resumes seeded allocation, while fresh uniform priors explore during cold start. Exploration items are never re-served as exploration. Reward contract (satisfaction / meaningful consumption / voluntary return — not raw clicks) is defined before any learning on it.
- **Three timescales, never conflated**: ephemeral session intent → decayed emerging/dormant interests → durable explicit preferences.
- **Multimodal inspection**: shortlist only; sampled frames first (any vision model), native video input as a later provider-route upgrade; the model judges actual content vs title (quality, real topic, clickbait mismatch) against the brief's rubric; results are cached and reused for embeddings. Fail-open to metadata-only evaluation.
- **Two planes and replay**: user evidence ledger and agent policy decision journal are separate append-only stores, cross-referenced by ID; policy artifacts never enter user evidence. Landed: schema V7 `policy_briefs`/`policy_hypotheses`/`policy_lessons`/`policy_outcomes` with append-only triggers, `recommendation/policy_journal.py` (`PolicyJournal` port + `SqlitePolicyJournal`), and `recommendation/trace.py`, which assembles the durable candidate → evaluation → admission → selection → expression → exposure → feedback chain and replays a persisted seed cohort through deterministic `SelectionService` without model or provider calls. Shadow RecommendationBrief rows now retain typed output, compiler inputs/diagnostics, context hash, route identity, and prompt/schema/context versions without writing user evidence.
- **No unexplained global recommendation constants**: behavioral quantities are learned per user or emitted as named, versioned, provenance-tagged defaults; resource/validity bounds remain explicit contracts.
- **Metrics** (ledger SQL): frontier expansion rate (headline), exposure/consumption gap, exploration vs exploit funnels, exploit-slot satisfaction guardrail.

### Provider-algorithm channels

Provider recommendation streams are first-class acquisition supply, not a passthrough: each provider manifest declares a channel registry (per `feed_id`: bias class `platform-popularity | platform-personalized | subscription-graph | editorial`, auth requirement). Anonymous and credentialed variants of the same feed are distinct channels. Every candidate carries `(provider, channel)` provenance; per-channel meaningful-engagement yield is learned per user via the same Thompson machinery. Landed: `ProviderManifest.channels` validates the FEED authoring rule and registers anonymous feeds (`bilibili:popular`, `bangumi:rank`, `v2ex:hot`) plus cookie-authenticated `bilibili:rcmd`; `DiscoveryProvenance` persists provider/channel end to end, with schema V8 backfilling pre-registry candidate rows. Replenishment fetches only channels allowed by the connected handle, round-robins their bounded pages, and admits `rcmd` with `bilibili:rcmd` provenance and no exploration attribution. Feed failures or missing credentials soft-degrade to the remaining feed/search supply.

Accepted feedback on any channel-attributed candidate resolves a standing, channel-namespaced policy hypothesis (for example `channel-bilibili-rcmd`) through the existing attempt/success/failure and Beta posterior machinery; this keeps channel yield per user in the append-only policy journal without a new store. `platform-personalized` remains exploit-only in both live attribution and the deterministic brief compiler. The posterior is measured and available for replay, but channel-level allocation remains the documented simple round-robin until enough single-user data justifies using those posteriors to choose supply volume. Other providers' personalized feeds are not implemented. `History` and `Saved` remain the next evidence-triggered channels.

Build order: two-plane contract → decision/exposure trace + replay → RecommendationBrief (shadow mode first) → selective multimodal inspection → statistical allocation → event-triggered profile re-synthesis → question delivery. Constraint-only slate construction is landed; semantic MMR similarity re-ranking waits for Phase C embeddings. Deferred until data proves need: control arms, dual veto, learned quota-envelope shifts, reflexion machinery.
